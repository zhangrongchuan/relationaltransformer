# RT 改进项目 · 中期答辩总结（从头到尾，大白话版）

> 一句话：我们先用数据证明了 RT 的 zero-shot 主要靠"抄历史标签"而非真推理，
> 然后从"训练目标 / 上下文构造 / 模型表示"三个方向做改动，最硬的结论是——
> **抄标签这个毛病只能在预训练起点预防，事后修反而更糟**。

---

## 0. 先搞清楚 RT 是什么（30 秒）

RT（Relational Transformer）是一个"关系数据库上的基础模型"：给它一个数据库（多张表、表之间有外键）和一个预测任务（比如"这个车手这场会不会退赛"），它把相关的数据行拆成一个个"格子"（每个格子 = 某行某列的值），拼成一个最多 **1024 格**的序列喂给 Transformer，用 attention 做预测。卖点是 **zero-shot**：在没见过的数据库上直接预测。

它怎么选那 1024 个格子？从"要预测的那一行"出发，沿外键做 BFS（广度优先搜索）随机抓相关的行。

---

## 1. 我们发现的 4 个问题（动机 · "前"）

1. **抄标签捷径**：预测目标行的历史标签会被直接放进 context，模型一层 attention 就能"抄"到，不用推理。
2. **采样太随机**：1024 个格子是随机抓的，同一个目标每次抓的不一样，且没有"优先抓最近事件"。
3. **预算浪费**：1024 里大部分花在跟目标无关的"周边装饰"上。
4. **没有时间感**：模型不知道每个事件距预测时刻多久（时间戳根本没进模型）。

论文自己的 ablation（Table 4）已经暗示了问题 1：去掉 self label 后分类 AUROC 从 70 掉到 54（接近瞎猜）。我们要做的是**把这些猜测变成数据，再逐个修**。

---

## 2. 诊断阶段：证明问题真的存在（不训练，只跑现成模型）

### 诊断脚本做了什么

- **`diag_context.py`** — 把每条 context 的 1024 个格子按"跟目标的关系"分类统计（目标行/历史标签/周边等），看预算花在哪、有多少可抄标签。
- **`diag_variance.py`** — 同一批目标，换 8 次随机 context 各预测一遍，看预测变不变、8 次平均（ensemble）会不会更准。
- **`diag_copy_baseline.py`** — 写一个**完全不学习的"作弊基线"**：只把 context 里同实体的历史标签平均一下当预测。用它当标尺，看 RT 比"纯抄"强多少。

### 诊断结果（三个问题全部坐实）

| 发现 | 数据 |
|---|---|
| 预算被周边吃掉 | 周边占 54%–98%，中位约 **90%** |
| 有些任务根本没标签可抄 | study-outcome / study-adverse 的 self-label = **0** |
| 采样噪声真实 | 换采样后 **34%–43%** 的预测翻面；8 次 ensemble 白涨 **+1.4~+3.4** |
| RT ≈ 抄标签 | 作弊基线在 user-engagement 0.846、user-badge 0.824 上**追平/超过** RT |
| 没标签就废 | study-outcome 上 RT 预测方差仅 0.03（近常数），AUROC 0.53≈瞎猜 |

**结论**：RT 的 zero-shot 很大程度是"高级抄标签"，一旦没标签可抄就不会推理。这就是我们要攻击的 gap。

---

## 3. 我们做的 5 个改动（方法 · "怎么修"）

分两类：**改采样（不用重训也能生效）** 和 **改模型/训练目标（必须训练）**。

### 改动清单

| 代号 | 改动 | 改哪个文件 | 属于哪类 | 通俗解释 |
|---|---|---|---|---|
| A | `time_rope` | rt/model.py | 训练期 | 让 attention 按"事件距预测时刻的时间差"旋转，模型就有了时间感 |
| E1 | `entity_flag` | rt/model.py | 训练期 | 给"属于目标实体的格子"打一个标记，告诉模型哪些是主角 |
| B | `self_label_dropout` | rustler/src/fly.rs | 训练期 | 训练时随机删掉可抄的历史标签，逼模型别抄、去推理 |
| C | `local_k` | rustler/src/fly.rs | 采样 | 保证目标实体**最近 K 个事件**一定进 context |
| P | `periphery_cell_cap` | rustler/src/fly.rs | 采样 | 每个"周边装饰行"最多贡献几个格子，省预算 |

### 每段代码具体做了什么

- **rt/model.py（加了约 85 行）**
  - `apply_time_rope()`：对 attention 的 query/key 按各自时间戳做旋转（RoPE），内积就只依赖"两个事件的时间差"。数据里本来就有时间戳，之前没人用，现在接上了。
  - `RelationalTransformer` 加了 `time_rope` / `entity_flag` 两个开关（默认关，兼容旧模型）。
  - `entity_flag` 打开时：找出属于目标实体的格子（目标行 + 它的外键邻居 + 引用了这些实体的行），给它们加一个可学习的标记向量。
- **rustler/src/fly.rs（加了约 101 行，这是那个 Rust 写的高速采样器）**
  - `self_label_dropout`：采样时，遇到"其他同实体行的目标列格子"（可抄的标签），以概率 p 跳过不放进 context。
  - `local_k`：BFS 之前先做一个"local 阶段"，把目标实体每类关系下**按时间排序最近的 K 个事件**优先塞进去。
  - `periphery_cell_cap`：判断一行是不是"周边装饰"（跟目标实体无关、非任务表），是的话最多写几个格子就停。
- **rt/data.py / rt/main.py**：把上面这些新参数从 Python 一路传到 Rust 采样器和模型，并区分"训练用"和"评测用"。
- **实验入口 / 评测脚本**
  - `train_variant.py`：统一的训练入口，一个命令切换"从零训练/继续训练"和任意组件组合。
  - `eval_ablation.py`：**无标签评测协议**——评测时把所有可抄标签删光，逼模型只能推理，测"真本事"。
  - `eval_sampling_variants.py` / `eval_paper_table.py`：噪声受控地评采样改动 / 在全量 test 上对齐论文表。
  - `collect_results.py` / `collect_paper_table.py`：把一堆日志汇总成对比表。

## 4. 实验怎么做的（三种训练方式 + 三种评测）

**三种训练方式**（论文也是这么分的）：
- **pretrain（从零）**：随机初始化训 50000 步，leave-db-out（目标库全程不见）→ 产出 zero-shot 模型。约 3 小时/个。
- **contd（继续训练）**：从官方 checkpoint 再训 8000 步。约 30 分钟/个。
- **inference（不训练）**：直接用官方 checkpoint，只改评测采样。几分钟~2 小时。

**三种评测**：
- 正常评测（标签在）、无标签评测（删光标签逼推理）、论文对齐评测（全量 test，对标论文表）。

**做过的实验规模**：L0 诊断 3 套 × 21 任务；组件网格 32 个 contd 训练；多 seed 确认 18 个；从零训练 4 个；各种评测约 30 个作业。

## 5. 结果（哪些成了、哪些没成）

### ★ 头牌成功：防抄标签，但**必须从预训练起点做**

driver-dnf（从零训练 50k 步，无标签评测 val）：

| | 正常评测 | 无标签评测 | 标签依赖度 |
|---|---|---|---|
| baseline | 0.676 | **0.366**（比瞎猜还低） | +0.310 |
| **drop09** | **0.706** (+3.0) | **0.570** (+20.3) | **+0.136**（减半） |

**对照（证明"时机"是关键）**：同样的 dropout 放到"继续训练"阶段（模型已学会抄），无标签成绩反而从 0.625 掉到 0.472。

**怎么理解**：像一个靠翻答案做题的学生。已经养成习惯后再撕答案（继续训练加 dropout）→ 他只会更拼命找剩下的答案，一旦没答案就崩。从第一天就没答案（从零加 dropout）→ 被迫真的学会做题，连有答案时也考得更好。这就是"双赢"，也是本项目最硬的结论。

### ✅ 成功但任务依赖：改采样（全量 test，对齐论文）

| 任务 | 论文 | 我们 baseline | +pcap4 | ensemble |
|---|---|---|---|---|
| rel-hm/user-churn | 62.8 | 64.3 | **66.4**(+2.1) | 65.3 |
| rel-f1/driver-dnf | 81.2 | 80.2 | 80.7 | **81.5** |
| rel-f1/driver-top3 | 89.3 | 88.7 | 89.2 | **90.1** |
| rel-stack/user-engage | 75.7 | 78.1 | **74.1**(-4.0) | 79.1 |
| **10 任务均值** | **69.7** | **70.0** | 69.6 | **70.4** |

**两个关键点**：
1. 我们的 baseline 均值 70.0 ≈ 论文 69.7 → **评测管线可信**（这本身是重要的校验结果）。
2. pcap4 **有的任务大涨（hm +2.1）、有的大跌（engage -4.0），平均打平** → **固定规则不行，"该砍哪些表"是任务相关的**。这正是"任务条件化预算" = schema-graph（还没做）的最强动机。
3. ensemble 是唯一稳定的小赢（均值 +0.4，F1 任务上更明显）→ 零成本可上榜。

（注：user-repeat 上 pcap4 曾复现 +4.2，但该任务不在论文这张 10 任务表里。）

### ⚠️ 半成 / 没定论

- **entity_flag**：继续训练下 study-outcome（唯一 0-label 任务）val **+1.2，三 seed 复现**（正好在理论预言的位置）；但从零训练不稳定（后段崩），需加归一化约束。
- **time_rope**：继续训练下中性偏弱正（ad-ctr +2.2 单 seed）；旋转会破坏预训练 attention，公平测试要从零训练，还没做。

### ❌ 有信息量的失败

- **只改 local、不配 pcap**：负效应（挤占预算）→ 证明组件必须成对。
- **继续训练阶段加 dropout**：反效果（见上）→ 证明必须从起点做。

## 6. 诚实的局限（答辩要主动讲，别被问）

1. **规模差距**：从零训练 50k 步的模型比官方 checkpoint 低约 6 分（同配置）。所以 drop09 的 +3.0/+20.3 是**等算力受控对照**，**不代表能超过论文 81.2**。要变成排行榜数字得完整规模重训。
2. **POSTRA 的图还没建**：我们借了 POSTRA/ULTRA 的**思想**（相对时间、labeling trick、remove-easy-edges、local/global），但**没有实现 relation/schema graph 本体**（组件 D）。目前最大的胜利（防抄标签）血统上是 NBFNet 的通用防捷径思想，不是 POSTRA 独有机制。要让论文名正言顺"引入 POSTRA"，D 是必须补的——而当前 pcap 的任务依赖结果正好给它铺好了动机。
3. **个别任务退化**：user-attendance 标签零膨胀，回归指标失真，已从回归结论里排除。

## 7. 答辩用的逻辑链（一页讲完）

```
RT 卖点是 zero-shot 关系基础模型
        │
问题：论文 ablation 显示去掉 self-label 就崩 → 怀疑它在抄标签
        │
诊断（我们的数据）：作弊基线≈RT；0-label 任务近瞎猜；预算 90% 浪费；采样翻面 40%
        │  ——三个瓶颈全部坐实
方法：三方向修 —— 训练目标(防抄标签) / 上下文(采样) / 表示(时间·实体标记)
        │
结果：① 防抄标签必须从起点做（无标签 +20，事后做反而 -15）★核心
      ② 采样任务依赖、平均打平 → 动机指向"任务条件化预算"(schema-graph)
      ③ ensemble 零成本 +0.4，baseline 复现论文(70.0 vs 69.7)校验管线
        │
下一步：(a) 完整规模坐实防抄标签  (b) 实现 schema-graph 做任务条件化 → 真正引入 POSTRA
```
